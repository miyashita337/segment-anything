# /pre-implementation-check - 実装前チェックリスト

## 概要

実装を開始する前に必須確認項目を検証するゲートチェック。

## 実行手順

### Gate 1: 要件理解

以下を明確にせよ:

- [ ] **目的**: 何を達成するか
- [ ] **スコープ**: どこまで実装するか
- [ ] **制約**: 変更してはいけない箇所

不明確な場合はユーザーに確認を求めよ。

### Gate 2: 影響度調査 (/impact-analysis)

```
/impact-analysis を実行
```

**確認項目**:
- [ ] 依存関係を把握した
- [ ] リスク評価を行った
- [ ] 影響を受けるモジュールをリストアップした

**ゲート条件**: 高リスクの場合はユーザーに承認を求めよ。

### Gate 3: アーキテクチャ整合性 (/architecture-review)

```
/architecture-review を実行
```

**確認項目**:
- [ ] 基本原則（SRP, DRY, YAGNI）に違反していない
- [ ] プロジェクト構造に適合している
- [ ] 循環依存を発生させない

**ゲート条件**: 違反がある場合は設計を見直せ。

### Gate 4: テスト先行 (/test-first)

```
/test-first を実行
```

**確認項目**:
- [ ] 失敗するテストを先に作成した
- [ ] テストの配置場所が適切

**ゲート条件**: テストなしでの実装開始は禁止。

### Gate 5: 既存コード理解

**確認項目**:
- [ ] 変更対象のコードを読んだ
- [ ] 類似機能の有無を確認した
- [ ] 再利用可能なコードを特定した

## 最終チェックリスト

```markdown
## 実装前チェック結果

### Gate通過状況
- [ ] Gate 1: 要件理解 ✅/❌
- [ ] Gate 2: 影響度調査 ✅/❌
- [ ] Gate 3: アーキテクチャ整合性 ✅/❌
- [ ] Gate 4: テスト先行 ✅/❌
- [ ] Gate 5: 既存コード理解 ✅/❌

### 実装開始可否
✅ 全Gate通過 → 実装開始可
❌ 未通過Gateあり → 実装開始禁止（理由: ...）
```

## 重要: 承認必須ルール

CLAUDE.mdより:

> **Phase移行時・破壊的操作前は必ず停止し「承認をお願いします」と明記してユーザーの返答を待つこと。承認なしでの続行は規約違反。**

以下の場合は必ずユーザー承認を得よ:
- 高リスク変更
- 複数モジュールへの影響
- 既存機能の修正・削除
