# 要件定義書

## 概要

ワークフロー開始前の計画・起票段階を管理する新しい`plan`コマンドシステムを実装します。これにより、質問→調査→起票→ワークフロー開始の流れを体系化し、既存のTaskFailureEscalation機能（旧PlanModeエスカレーション）は維持します。

## 要件

### 要件1: Plan コマンドシステム

**ユーザーストーリー:** 開発者として、トラッカーのワークフローを開始する前に、適切な計画と起票を行いたい。

#### 受入基準
1. WHEN `plan {TRACKER_ID} {概要} {詳細}`コマンドを実行する THEN システムはGoogle Sheetsにトラッカーを起票する
2. WHEN 3つの引数が提供される THEN システムは全ての引数を必須として検証する
3. WHEN 詳細が20,000文字を超える THEN システムはエラーメッセージを表示する
4. WHEN 起票が成功する THEN システムは確認メッセージを表示する
5. WHEN 起票が失敗する THEN システムは詳細なエラー情報を提供する

### 要件2: Create コマンド分離

**ユーザーストーリー:** 開発者として、起票済みのトラッカーでワークフローを開始したい。

#### 受入基準
1. WHEN `create {TRACKER_ID}`コマンドを実行する THEN システムはSQLiteワークフロー状態管理のみを開始する
2. WHEN Google Sheets起票機能が呼ばれる THEN システムはエラーを返す（機能削除済み）
3. WHEN SQLiteワークフロー開始が成功する THEN システムは現在のステップを表示する
4. WHEN トラッカーが既に存在する THEN システムは適切な警告を表示する
5. WHEN ワークフロー開始が失敗する THEN システムは詳細なエラー情報を提供する

### 要件3: TaskFailureEscalation機能保持

**ユーザーストーリー:** システム運用者として、既存のタスク失敗時の自動エスカレーション機能を維持したい。

#### 受入基準
1. WHEN タスクが失敗する THEN システムはTaskFailureEscalationを作成する
2. WHEN エスカレーションが作成される THEN システムは推奨アクションを自動生成する
3. WHEN Pushover通知が送信される THEN システムは適切な優先度で通知する
4. WHEN エスカレーションファイルが作成される THEN システムは適切な形式で保存する
5. WHEN 既存機能が呼ばれる THEN システムは従来通りの動作を保証する

### 要件4: 用語統一とリファクタリング

**ユーザーストーリー:** 開発者として、混乱を避けるために適切な用語を使用したい。

#### 受入基準
1. WHEN PlanModeエスカレーション用語が使用される THEN システムはTaskFailureEscalationに変更する
2. WHEN クラス名が変更される THEN システムは`PlanModeEscalator`を`TaskFailureEscalator`に変更する
3. WHEN ファイル名が変更される THEN システムは`planmode_escalation.json`を`task_failure_escalation.json`に変更する
4. WHEN 関数名が変更される THEN システムは適切な命名規則に従う
5. WHEN ドキュメントが更新される THEN システムは全ての参照を新しい用語に更新する

### 要件5: 後方互換性とマイグレーション

**ユーザーストーリー:** システム運用者として、既存のワークフローに影響を与えずに新機能を導入したい。

#### 受入基準
1. WHEN 既存のcreateコマンドが実行される THEN システムは新しい動作で正常に実行する
2. WHEN 既存のTaskFailureEscalation機能が呼ばれる THEN システムは従来通りの動作を保証する
3. WHEN 設定ファイルが参照される THEN システムは新旧両方の形式をサポートする
4. WHEN マイグレーションが必要な場合 THEN システムは自動的に新形式に変換する
5. WHEN エラーが発生する THEN システムは適切なフォールバック処理を実行する

## 非機能要件

### パフォーマンス
- planコマンドの実行時間は5秒以内
- createコマンドの実行時間は3秒以内
- Google Sheets API呼び出しのタイムアウトは30秒

### セキュリティ
- 詳細情報の文字数制限による入力検証
- SQLインジェクション対策
- ファイルパス検証

### 可用性
- Google Sheets API障害時の適切なエラーハンドリング
- SQLiteデータベース障害時の復旧機能
- ネットワーク障害時のリトライ機能

### 保守性
- 明確な責任分離（plan: Google Sheets、create: SQLite）
- 適切なログ出力
- エラーメッセージの国際化対応（日本語）
