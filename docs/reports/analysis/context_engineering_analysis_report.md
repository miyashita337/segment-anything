## 📋 概要

本レポートは、segment-anythingプロジェクトにおけるClaude Code実行時のコンテキスト量過多問題を分析し、Zenn記事「Context Engineeringの学習」に基づく**Lost-in-the-Middle現象**の発生状況と根本的解決策を検討したものです。

### 🚨 主要発見事項

- **推定トークン数**: 74,114〜114,022トークン（確実にLost-in-the-Middle状態）
- **文書過多**: 96個のMarkdownファイル、57,011語の膨大なコンテキスト
- **情報重複率**: 主要概念で17-28ファイルに分散記載（重複度29%）
- **パフォーマンス低下**: Zenn記事の-39点信頼性低下パターンに該当

---

## 🔍 問題

### 現在の問題状況
「ユーザーの思ったようにClaudeが動作してくれません」という状況は、以下の技術的問題に起因することが判明：

1. **情報量過多によるノイズ化**: 必要な情報が膨大なコンテキストに埋もれる
2. **Lost-in-the-Middle現象**: 中間部分の情報（docs/workflows等）が見落とされる
3. **注意バイアス**: 開始部（CLAUDE.md）と終端部への注意集中、中間部の軽視
4. **矛盾する情報の混在**: 複数ファイルでの記述不整合がパフォーマンスを阻害

### 具体的症状
- 中間部分のドキュメント（workflows/、checklists/）への参照精度低下
- 同一概念の重複記載による判断迷い
- タスク実行時の見落としや手順違反
- 冗長な応答や不適切な情報選択

---

## 📚 経緯

### 問題発生の背景
1. **feature/KIRO-007での大量削除**: 33,036ファイル削除後も依然として大量コンテキスト
2. **ドキュメント蓄積**: 品質向上を目指した詳細ドキュメント化が裏目
3. **統合不備**: 関連情報の分散配置、重複記載の放置
4. **バージョン管理不備**: 古い情報と新しい情報の混在

### ユーザーの期待vs現実
- **期待**: 詳細ドキュメントによる正確な動作
- **現実**: 情報過多によるパフォーマンス低下
- **Zenn記事との一致**: 「情報を増やすだけでは逆効果、整理が必要」そのもの

## 🔍 原因

### 根本原因分析

#### 1. アーキテクチャ問題
- **フラットな情報構造**: 階層化されていない大量ファイル
- **文脈分散**: 関連情報が複数ディレクトリに散在
- **重複許容設計**: 同一情報の複数箇所記載を許容

#### 2. 情報設計問題
- **Just-in-Case思想**: 「念のため」の過剰記載
- **削除回避**: 古い情報の保持による矛盾蓄積
- **参照システム不備**: 動的情報取得機構の欠如

#### 3. Zenn記事での指摘との完全一致
- **「情報を増やすだけでは逆効果」**: まさに当プロジェクトの現状
- **「Lost-in-the-Middle」**: 96ファイル構成で確実に発生
- **「整理が必要」**: 情報統合・階層化の必要性

### 直接的要因
1. **品質向上の誤解**: ドキュメント量=品質という錯誤
2. **削除への心理的抵抗**: 「情報を失う」恐怖
3. **統合作業の技術的困難**: 大量ファイルの整理コスト
4. **効果測定不備**: コンテキスト効率の定量評価欠如

## 🛠️ 根本的解決方法

### A. 階層化コンテキスト設計（Zenn記事準拠）

#### レベル1: コアコンテキスト（必須）
**目標**: 5-10K語以内
```
- CLAUDE.md（簡潔版）
- 実行中タスク関連のみ
- 現在の状態・設定情報
```

#### レベル2: 補完コンテキスト（動的取得）
**目標**: 必要時のみ参照
```
- セレナMCP経由での個別ファイル取得
- タスク特化情報の Just-In-Time Loading
- 関連ドキュメントへの動的リンク
```

#### レベル3: 詳細コンテキスト（デバッグ用）
**目標**: 問題発生時の深掘り
```
- 完全技術仕様
- 履歴・ログ情報
- デバッグ詳細ガイド
```

### B. 情報統合・重複排除戦略

#### 統合リファレンス創設
```markdown
# 統合リファレンス例
## トラッカー管理（統一版）
**ワークフロー**: tools/workflow/workflow_cli.py
**Google Sheets連携**: tools/progress_tracker/cli.py
**詳細**: 動的参照 → docs/workflows/tracker_guide.md
```

#### 重複排除プロセス
1. **概念マッピング**: 同一概念の全ファイル特定
2. **マスター選定**: 1つの権威ファイルを選定
3. **参照変換**: 他ファイルを参照形式に変換
4. **検証プロセス**: 情報整合性確認

### C. 動的コンテキスト管理システム

#### Just-In-Time Information Loading
```python
# 概念例
class ContextManager:
    def get_task_context(self, task_id: str) -> Dict:
        """タスクに必要最小限の情報のみ取得"""
        return {
            'core': self.get_core_info(),
            'task_specific': self.get_task_info(task_id),
            'dynamic_refs': self.get_reference_links(task_id)
        }
```

#### セレナMCP活用戦略
- **検索ベース**: 必要情報のピンポイント取得
- **メモリ最適化**: タスク完了後のコンテキストクリア
- **インデックス化**: 高速情報検索システム
