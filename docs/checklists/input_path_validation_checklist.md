# 入力パス検証チェックリスト

## 🛡️ **必須検証プロセス**

### Phase 1: 入力パス受信時の即座検証

#### ✅ **必須チェック項目**
- [ ] **1. 入力パス存在確認完了**
  - 指定されたパスが実際に存在するか`ls`コマンドで確認
  - 確認コマンド: `ls [指定パス]`
  
- [ ] **2. 存在しない場合、即座停止実行**
  - パスが存在しない場合、一切の処理継続を禁止
  - 代替案提案・回避策検討を完全禁止
  
- [ ] **3. 統一エラーメッセージ使用**
  - CLAUDE.md準拠の統一エラーメッセージ形式を使用
  - 以下のテンプレートを厳格に適用
  
- [ ] **4. 代替案提案を回避**
  - 「kana05を使用」等の代替案提案を完全禁止
  - 「とりあえず作成」「空で進める」等の回避策禁止

### Phase 2: エラーメッセージテンプレート

```bash
❌ エラー: 入力ディレクトリが存在しません
   パス: {指定されたパス}

🔧 対処方法:
   1. パスの確認: ls {親ディレクトリ}
   2. 正しいパスの指定
   3. 必要に応じてディレクトリ作成

⚠️ 注意: 存在しないパスでの強制実行は品質保証違反です
```

### Phase 3: 禁止行為の明確化

#### ❌ **絶対禁止事項**
1. **処理継続**: 存在しないパスでの処理継続
2. **代替案提案**: 別のデータセット使用提案
3. **回避策検討**: 「とりあえず」「一旦」等の一時的解決策
4. **エラー隠蔽**: 存在確認結果の曖昧な報告

#### ✅ **必須実行事項**
1. **即座確認**: 入力パス受信と同時に存在確認
2. **即座停止**: 不存在検出時の処理完全停止
3. **明確報告**: 統一エラーメッセージでの状況報告
4. **完全終了**: 追加処理・代替案検討の完全回避

## 🎯 **実装時のフロー**

```
ユーザー指示受信
    ↓
入力パス抽出
    ↓
ls コマンドで存在確認
    ↓
存在？ → YES → 処理継続
    ↓
    NO → 統一エラーメッセージ返却 → 処理完全停止
```

## ⚠️ **品質保証原則**

**「存在しないパス → 即座エラー → 処理停止」**

この原則を**例外なく100%適用**する。

## 📋 **チェックリスト実行例**

### 正しい実行例
```
入力: /mnt/c/AItools/lora/train/yado/org/TEST-001/
確認: ls /mnt/c/AItools/lora/train/yado/org/TEST-001/
結果: 存在しない
対応: 統一エラーメッセージ返却 + 処理停止
```

### 間違った実行例（厳禁）
```
入力: /mnt/c/AItools/lora/train/yado/org/TEST-001/
確認: ls /mnt/c/AItools/lora/train/yado/org/TEST-001/
結果: 存在しない
対応: 代替案としてkana05を使用 ← 仕様違反
```

## 🚨 **違反時の対処**

もし上記チェックリストに従わない処理を実行した場合：
1. 即座に処理を中断
2. このチェックリストを再確認
3. 正しい手順で再実行

**品質保証のため、このチェックリストは絶対遵守事項です。**
