### 技術的困難発生時
```bash

2. 試行済み解決策の記録
3. 可能な選択肢の提示
4. ユーザー確認・指示待ち
```

### 計画変更が必要な場合
```bash
# 計画承認の再取得手順
1. 変更理由・影響範囲の分析
2. 修正計画書の作成
3. ユーザー承認の再取得
4. 修正計画に基づく実行
```

### 品質基準未達成時
```bash
# 品質改善・再実行手順
1. 品質劣化要因の分析
2. 改善策の立案・実行
3. 品質ワークフロー再実行
4. 基準達成まで反復改善
```
