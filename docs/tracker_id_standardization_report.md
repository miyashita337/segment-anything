## 🎯 標準化提案

### 推奨アプローチ: ハイブリッド方式

既存システムの安定性を保ちつつ、新規トラッカーから段階的標準化を実施。

#### 新規トラッカー命名規則

```
[機能コード]-[連番] 形式

例:
- QUAL-001  # 品質管理 (Quality)
- EXTR-001  # 抽出処理 (Extraction)  
- INTG-001  # 統合処理 (Integration)
- TEST-001  # テスト作業 (Testing)
- DOCS-001  # ドキュメント (Documentation)
- PHSE-001  # Phase作業 (Phase)
```

#### 機能コード定義

| コード | 機能領域 | 説明 | 従来の対応 |
|--------|----------|------|------------|
| **QUAL** | 品質管理 | 品質評価・改善・監視 | QCC-*, QI-* |
| **EXTR** | 抽出処理 | キャラクター抽出・分割 | SAM/YOLO関連 |
| **INTG** | 統合処理 | システム統合・CI/CD | CI-*, INTEGRATE-* |
| **TEST** | テスト作業 | テスト・実験・検証 | T-*, TEST-* |
| **DOCS** | ドキュメント | 文書作成・更新 | DOC-* |
| **PHSE** | Phase作業 | フェーズ別開発作業 | PH1-*, PH2-*, etc |
| **OPTM** | 最適化 | パフォーマンス・メモリ最適化 | CLAUDE-OPT-* |
| **MAINT** | メンテナンス | 保守・クリーンアップ | CLEANUP-*, MAINT-* |

### 新規トラッカー作成手順

1. **機能分析**: トラッカー作成前に機能領域を特定
2. **コード選択**: 8つの機能コードから最適なものを選択
3. **連番確認**: 同一機能コード内での最新連番を確認
4. **命名実行**: [機能コード]-[連番]形式で作成
