# Claude Code Hook設定管理ポリシー

## 概要

`.claude/hooks.json`ファイルは通常`.gitignore`で除外されていますが、重要なシステム機能変更時には例外的にコミットする必要があります。

## 基本方針

### 🚫 通常はコミットしない理由

1. **個人設定の性質**: ローカル開発環境特有の設定が含まれる
2. **秘匿情報**: 個人の認証情報や環境固有のパスが含まれる可能性
3. **環境依存**: 開発者ごとに異なる設定が必要な場合

### ✅ コミットすべき場合

以下の条件を**全て**満たす場合は`git add -f .claude/hooks.json`でコミット：

#### 1. システム機能の重要な変更
- ワークフロー制御の根本的な変更
- 品質保証システムの更新
- セキュリティ関連の Hook 追加・変更

#### 2. チーム全体への影響
- 全開発者が同じ Hook 設定を使用する必要がある
- CI/CD パイプラインで必要な設定
- プロジェクト標準化の一部

#### 3. バージョン管理の必要性
- 設定変更履歴の追跡が必要
- ロールバックの可能性がある
- デプロイ時に本番環境で必要

## 実践例

### ✅ コミットした例（INTG-087）

```json
{
  "PreToolUse": {
    "command": "bash tools/hooks/semantic_workflow_compliance.sh",
    "description": "INTG-087: セマンティックワークフロー検証"
  }
}
```

**理由**: 
- セマンティックワークフロー検証は全チームで統一が必要
- 品質保証システムの重要な機能変更
- プロジェクト標準化の一部

### ❌ コミットしない例

```json
{
  "PostToolUse": {
    "command": "notify-slack --user john --token secret123"
  }
}
```

**理由**:
- 個人の通知設定
- 秘匿情報（トークン）を含む
- 環境依存設定

## 判定フローチャート

```
Hook設定変更
      ↓
システム機能の重要変更？
      ↓ YES
チーム全体への影響？
      ↓ YES  
秘匿情報を含まない？
      ↓ YES
git add -f .claude/hooks.json
      ↓
コミット・プッシュ
```

## 注意事項

### コミット前チェック
- [ ] 秘匿情報（APIキー、パスワード等）が含まれていない
- [ ] 環境固有のパス（個人のホームディレクトリ等）が含まれていない
- [ ] 他の開発者の環境でも動作する設定になっている
