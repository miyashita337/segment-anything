# Tools Directory ガバナンスルール

TDR-003により確立されたTools Directoryの管理ルールとガイドライン。

## 📁 ファイル配置ルール

### 新規ファイル作成時の配置基準

#### core/ - 中核ツール
- **対象**: 継続的に使用される重要な機能
- **例**: API統合、品質チェック、パイプライン実行
- **基準**: 
  - 他のツールから参照される
  - プロジェクトの中核機能
  - 長期間保守される
- **禁止**: 一時的な処理、実験的コード

#### batch/ - バッチ処理系
- **対象**: データセットの一括処理スクリプト
- **例**: kana08処理、一括抽出、評価バッチ
- **基準**:
  - 大量データの処理
  - 長時間実行
  - 再現可能な処理
- **禁止**: 単発実行、手作業代替

#### testing/ - テスト・評価系
- **対象**: テストスクリプトと評価ツール
- **例**: phase2テスト、品質評価、ベンチマーク
- **基準**:
  - test_で始まるファイル名
  - 検証・評価目的
  - 回帰テスト対応
- **禁止**: 本番データ処理、実装コード

#### scripts/ - 一時的・特定目的
- **対象**: 特定タスク用の実行スクリプト
- **例**: リリース処理、データ移行、修正スクリプト
- **基準**:
  - 一回限りまたは短期間の使用
  - 特定の問題解決
  - タスク完了後にdeprecated/移動対象
- **警告**: 30日経過で自動アーカイブ対象

#### utils/ - ユーティリティ
- **対象**: 共通的なユーティリティツール
- **例**: モデル初期化、リポジトリ整理、監査
- **基準**:
  - 複数の場所から利用
  - 汎用的な機能
  - 依存関係が少ない
- **禁止**: 特定ドメインに特化した処理

#### legacy/ - レガシー・重複機能
- **対象**: 将来的に削除・統合予定のファイル
- **例**: 重複した読み取りツール、旧バージョン
- **基準**:
  - より良い代替手段が存在
  - 後方互換性のためのみ保持
  - 積極的な削除対象
- **アクション**: TDR-004で統合・削除予定

## 🔄 ライフサイクル管理

### ファイルの自動管理

#### 1. 作成時チェック
```bash
# 新規ファイル作成前に実行
python tools/manager.py validate new_script.py
```

#### 2. 定期メンテナンス（週次推奨）
```bash
# 古いファイルの確認
python tools/manager.py cleanup --days 30

# 統計確認
python tools/manager.py stats

# ガバナンス準拠チェック
python tools/manager.py governance-check
```

#### 3. 月次レビュー
- scripts/ディレクトリの全ファイル見直し
- legacy/ディレクトリの削除検討
- 使用頻度の低いcore/ファイルの見直し

### アーカイブ戦略

#### 自動アーカイブ対象
- **scripts/**: 30日未更新
- **完了タスク関連**: ステータス"/release"から30日経過
- **重複ファイル**: 機能統合完了時

#### 手動アーカイブ対象
- **実験的実装**: 正式版完成時
- **一時的修正**: 恒久対応完了時
- **レガシー**: 代替実装完了時

#### アーカイブ先
```
deprecated/
├── tools_archive/           # 使用済みツール
├── experimental/           # 実験的実装
└── legacy_backup/          # レガシーバックアップ
```

## 📊 品質基準

### コード品質
- **flake8準拠**: 必須
- **型ヒント**: 推奨（core/は必須）
- **docstring**: 公開関数は必須
- **テスト**: core/とbatch/は単体テスト推奨

### ファイル命名規則
- **core/**: 機能名_用途.py (例: google_sheets_updater.py)
- **batch/**: データセット名_処理内容_batch.py (例: kana08_enhanced_stable_batch.py)
- **testing/**: test_対象機能.py (例: test_phase3_cli.py)
- **scripts/**: タスクID_処理内容.py (例: p1_a001_release.py)
- **utils/**: 機能名.py (例: init_models.py)

### 依存関係管理
- **core/**: 最小限の外部依存
- **batch/**: core/とutils/への依存OK
- **testing/**: 全ディレクトリへの依存OK
- **scripts/**: 必要に応じて依存OK（一時的のため）
- **utils/**: 他ディレクトリへの依存禁止

## 🚨 禁止事項

### 絶対に行ってはいけないこと
1. **プロジェクトルートへのスクリプト配置**
2. **tools/直下への新規ファイル作成**（README.md等を除く）
3. **一時ファイルの永続化**
4. **機密情報を含むファイルのcommit**
5. **大容量ファイル（>10MB）の配置**

### 警告対象
1. **scripts/での長期間ファイル保持**（30日超過）
2. **同一機能の重複実装**
3. **命名規則違反**
4. **適切でないディレクトリへの配置**
